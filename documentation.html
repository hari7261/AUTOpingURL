URL Ping Tool Documentation

This page explains how your monitoring tool works, what every file does, how to verify that data is real, and how to troubleshoot when you do not see updates.

1) What This Tool Does

The project pings one URL many times, stores request-level logs, calculates summary metrics, and displays all results in a dashboard.

  • Target URL: https://hari7261.github.io/INDUS/index.html
  • Requests per run: 500
  • Runs: scheduled every 2 minutes + manual run

2) Trigger and Schedule

The workflow is in .github/workflows/ping-url.yml. It runs by cron and can be started manually from GitHub Actions.

  • Cron: */2 * * * * (every 2 minutes)
  • Manual: Actions tab -> workflow -> Run workflow

3) Data Files

Generated files used by the dashboard:

  • logs/requests.log: Every request line with timestamp, status, latency
  • logs/latest-summary.json: Latest run metrics
  • logs/runs.ndjson: History of run summaries for chart trend

4) Dashboard Data Flow

  1. index.html fetches latest summary + history + request log
  2. Metric cards show summary values
  3. Canvas chart shows avg/min/max latency trend
  4. Log panel supports filter, search, sort, and pagination
  5. Auto-refresh runs every 10 seconds

5) How To Confirm It Is Working

  1. Open GitHub Actions and check latest run is green/success.
  2. Verify logs/latest-summary.json has a recent run_timestamp_utc.
  3. Verify logs/requests.log gets new lines after a run.
  4. Verify logs/runs.ndjson gets one new line per run.
  5. Open dashboard and check cards/chart/logs change after refresh.

6) Common Issues and Fixes

  • No data visible: confirm workflow run succeeded and logs were committed.
  • Stale dashboard data: hard refresh browser to bypass cache.
  • Logs empty: check target URL availability and Action job output.
  • High failures/non-200: inspect status_breakdown in summary JSON.
  • Slow page load with huge logs: use filters and lower rows-per-page.

7) Tuning Settings

You can change values in workflow environment variables:

  • REQUEST_COUNT: how many pings per run
  • CONCURRENCY: parallel requests
  • REQUEST_LOG_LIMIT: max request log lines retained
  • RUNS_HISTORY_LIMIT: max summary history lines retained
